# Support handoffs: remembering the investigation

Document ID: SUPPORT-06. Revision: 1. Owner: Studio IT.

## Recording an episode

A useful support episode identifies the symptom, relevant conditions, attempted step, and observed outcome. Distinguish a recommendation from a step that was actually attempted. An answer sent successfully is not evidence that the user's problem was resolved.

## Using a previous case

Recall earlier incidents to form a hypothesis and avoid repeating an investigation. Check the current error and environment before applying a remembered fix. When a previously useful step fails, retain that failure as part of the case and consult the applicable guide for the next step.

## Handing the case to another agent

Preserve the ticket ID, the exact attempted steps, their outcomes, and the guide references. Open the same authorized memory store under the user's identity when a second support agent takes over. Starting a new agent does not require restarting the investigation, but the receiving agent must still check whether circumstances changed.

## Separating sources of information

These runbooks state approved procedures, semantic facts describe a user's environment, and episodic entries describe particular interactions. Working memory carries information through the current request, while procedural memory may later hold a separately evaluated reusable skill. Do not promote a single remembered success into studio policy.
