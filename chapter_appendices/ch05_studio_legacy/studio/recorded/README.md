# Recorded studio walkthrough

[trace.json](trace.json) and [transcript.md](transcript.md) were generated by the studio walkthrough in scripted mode during revision 0.10 validation. The trace uses the actual Helix agent loop, memory hooks, learner, and archive, with fixed responder behavior and simulated support outcomes. It illustrates mechanics and is not a model-performance measurement.

The final validation ran the walkthrough in an isolated temporary directory and verified its outcomes, tool calls, version increments, and user-scoped handoff. These two text artifacts preserve the observed trace without shipping the temporary SQLite stores. The trace includes the corpus and ticket hashes, encoder identity, model mode, prompt hash, and fixed learning settings.

Reproduce it with `python chapters/ch05/03_memory_learning.py` from the repository root. A fresh run creates new entry IDs and a new output directory, while the E1 through E4 aliases and scripted value updates remain comparable. Use the guide hashes and configuration when comparing a later revision of the example.

The trace itself is preserved from the original recording. Revisions 0.13 and 0.14 reorder the teaching files without changing its scripted actions, prompt, guides, or fixed learning settings.

Revision 0.15 adds a `measurement` object to newly generated traces and prints the verified-resolution count. The original recording predates that reporting field; its four outcomes and memory updates remain the same. Three resolutions out of four requests describe the scripted run and do not establish improvement over a control.
